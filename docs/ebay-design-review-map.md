## C) Final OAuth URL design, as the revised design states it

**Authorize URL** (§1 "Authorize", "Scope encoding"): `https://auth.ebay.com/oauth2/authorize?client_id&response_type=code&redirect_uri=<RuName>&scope=<list>&state`; sandbox host `https://auth.sandbox.ebay.com/oauth2/authorize`. `redirect_uri` is the RuName verbatim, not a URL. `scope` is built by hand — `"scope=" + scopes.map(encodeURIComponent).join("%20")` — "never through `URLSearchParams`/`searchParams.set`, which would emit `+`"; `commerce-ebay-oauth.test.js` pins `%20` and the absence of `+`. `state = base64url(randomBytes(32))`, opaque to eBay.

**Accept (callback) URL** — the RuName's "auth accepted URL" (§1 "RuName"; §5 diagram): `https://nivadesk.app/ebay/callback`. eBay arrives with `?code&state&expires_in`. `app/ebay/callback/route.ts` (§5.1, §11.4) "forwards every param untouched + `nonce=<cookie value>`" to `https://europe-west2-eggcraft-studio.cloudfunctions.net/ebayOAuthCallback`, expires the `nv_ebay_nonce` cookie on the redirect response, `dynamic = "force-dynamic"`, and "still reads or rewrites no eBay parameter".

**Decline / rejection URL** — the RuName's "auth declined URL" (§1): `https://nivadesk.app/settings?section=ebay&ebay=cancelled`. §5 adds that the callback function also maps an `error` query param to `ebay=cancelled` as "defence only", since "eBay's declined URL normally lands on the settings page directly".

**Sandbox vs production RuName** (§1 "RuName"; §3 non-secret config; §7.7; §15 step 7): "Per keyset (sandbox and production have separate RuNames and separate app keys) … Owner registers both in the developer portal." The runtime holds one `NIVADESK_EBAY_RUNAME` and one `NIVADESK_EBAY_ENVIRONMENT` (`sandbox` default | `production`), both read "through getters at call time"; the state doc stores `redirectRuName` and `environment`, and a callback whose state `environment !== environment()` → `reason=environment`. Hosts follow the environment (`api.ebay.com` / `api.sandbox.ebay.com` for tokens, `apiz.ebay.com` / `apiz.sandbox.ebay.com` for identity). At the flip the owner sets "the production RuName/env" (§15 step 7) and runs `purgeEbaySandboxRows` (§7.7); rows with the old environment are skipped with `environment_mismatch`. There is no separate env var per environment — separation is by value at flip time plus the per-row filter.

**Callback function redirect targets** (§3 table `ebayOAuthCallback`; §5 "Redirect helper"): `302` to `https://nivadesk.app/settings?section=ebay&ebay=connected|cancelled|error&reason=…`, built by `connectRedirect(res, params)` = `new URL(appReturnUrl())`, `section=ebay`, then each param. Success target: `/settings?section=ebay&ebay=connected`.

**Error words** (§5 `ebayOAuthCallback` bullet; sentences in §10):
- `error` param present → `ebay=cancelled`
- `reason=missing_code` — missing `state`/`code`
- `reason=browser` — missing `nonce` or hash mismatch (state burned)
- `reason=disabled` — connector switch off
- `reason=state` — replay / expiry / unknown state
- `reason=environment` — state environment ≠ server environment
- `reason=no_seller` — identity call 403 (scope not granted)
- `reason=token` — throw classified `auth` by `classifyTokenError`; `reason=exchange` — any other throw
Each becomes a sentence only through `ebayReasonText` (§10: "a technical code never reaches the screen").

**Native start URL** (§5.2, §12): `https://nivadesk.app/ebay/start?state=<state>` — the app calls `beginEbayConnect({ origin:"native" })` (reply carries no nonce), never opens the authorize URL itself; `app/ebay/start/page.tsx` requires a signed-in web session, calls `claimEbayConnectState({ state })`, sets the cookie exactly as §5.1 and redirects to eBay; the callback still ends on nivadesk.app and the app re-polls `getEbayConnections`.

**Web section** (§5.1, §11.3): `setEbayNonceCookie(nonce)` is "the one place the cookie string is written", then `window.location.href = authorizeUrl`.

**What the operator enters in the eBay developer portal** (names only; §1, §3, §9, §15 "Owner actions"):
- Two keysets — sandbox and production (App ID / Client ID → secret `EBAY_CLIENT_ID`; Cert ID / Client Secret → secret `EBAY_CLIENT_SECRET`); the production keyset "only after sandbox acceptance".
- One RuName per keyset with "auth accepted URL" = `https://nivadesk.app/ebay/callback` and "auth declined URL" = `https://nivadesk.app/settings?section=ebay&ebay=cancelled`; the RuName value is env `NIVADESK_EBAY_RUNAME`.
